日期：2026-11-16　对应：第二版计划 3 Task 14，设计文档成功标准 5（Windows 部分）

## 环境和做法

- Windows 11 家庭中文版（10.0.26200），屏幕缩放下的实际窗口；pywebview 6.2.1，后端 `edgechromium`（WebView2，内核 Edg/157）；Python 3.13.7；SimpleCADAPI 2.2.7。
- 命令：`.venv\Scripts\caliper --demo-script scripts\demo_script.json`。这是**真的桌面窗口**（不是浏览器），模型换成假模型剧本（带孔的安装板），**沙盒是真的**：每次建模、终检、参数扰动、导出都在真实 SCA 里跑。
- 为了不碰任何真实的密钥：启动时把七个服务的密钥环境变量全部去掉；钥匙串用 keyring 的空后端（`PYTHON_KEYRING_BACKEND=keyring.backends.null.Keyring`，读出来永远是"没有"，系统钥匙串一次都没读）；数据目录 `CALIPER_HOME` 指到一个临时目录。整个走查没有调用任何模型服务。
- 截图都是窗口区域的截屏，放在 `docs/walkthrough/`。系统是深色模式，所以"跟随系统"时窗口是深色（蓝图）。

## 走查里发现并当场修掉的问题

1. **建模途中模型页签不显示已经通过的阶段。** 计划要求"正在建模、还没有版本时，加载 current 的各阶段 STL，新阶段通过时自动切过去"，但"有哪些阶段的 STL"只在一轮结束时的完整状态里更新。修法：页面收到 `stage` 事件时把这个阶段记进 `stage_files`（STL 在这之前已经导出）。先加了 node 测试 `test_stage_event_adds_stage_file`，看到它失败再改。第 21 步在真窗口里验证了。
2. **剧本模式下重开会话，剧本从头再来。** 走查用的 `--demo-script` 每次造智能体都从剧本第一条开始，重开后发一条消息会拿到"先问两件事"。修法：剧本跳过这个会话日志里已经用掉的回复数，剧本末尾加一条普通回复给重开后用。先加了测试 `test_demo_script_resumes_where_the_session_left_off`，看到它失败再改。这只影响开发用的剧本模式。
3. **最小窗口时右边被切掉。** pywebview 的最小尺寸 1100×700 是连边框算的，页面本身只有一千零八十几像素宽，而三栏的下限加起来正好 1100。修法：只在页面宽度不到 1100 时（也就是最小窗口那种情况）左栏从 240 收到 220、两栏下限放到 400 / 420；页面宽度 1100 及以上时仍是计划写的 240 / 420 / 440。第 20 步验证了。
4. **工作台标题栏的那一条区域看起来像压住了列表。** 实际是列表在那里截断、标题栏左边是空白，看着像重叠。给标题栏那一条加了一根细分隔线。

在这之前（Task 8 到 12 的看一遍里）还修过：三栏一开始没撑满高度、按 F5 重新加载后落到 403（加了用本标签页存的令牌重新进来的小页面）、设置页填价格时整页重画把先填的值弄丢、参数说明在窄窗口里挤成一字一行、改参数失败后输入框还显示新值、停止卡片的说明重复、版本对比要往下翻才看得到。

## 已知问题（修不了或没验证的，如实写）

1. **窗口高度拉到 700 那一下没有在真窗口里亲手做到。** 第一次打开时窗口底边在任务栏后面，拖不到；要把窗口挪上来需要控制桌面外壳，我没有申请这个权限。第二次打开时窗口位置靠上，拖右下角一次把宽高都拉到了最小（第 20 步），所以最小尺寸 1100×700 是看过的；但"只改高度"的情况没有单独看。
2. **在窗口里按 F5 没有反应。** pywebview 的窗口似乎不响应 F5，所以服务端"没带令牌时用本标签页的令牌重新进来"的小页面在真窗口里没有被触发过（在应用内置浏览器里验证过）。窗口里没有地址栏，正常使用碰不到这种情况。
3. **3D 区域空白（只出现过一次）。** Task 10 时有一次改完参数自动切到新版本后 3D 是空的（相机坐标算坏了），之后没有复现，原因没找到；加了"每一帧检查相机，坏了就重新取景"的保护，这次走查里没再出现，但保护本身没有被触发验证过。
4. **"失败"和"出错"两种卡片没有在真窗口里看到**（剧本里没有失败的情况）；"停止"卡片在 Task 9 的浏览器走查里看过，它们是同一个函数画的。"WebGL 不可用"的退回只测了判断逻辑，没有在关掉 WebGL 的电脑上看过。
5. **没有在 Mac 上看过**（计划 4 由组员照清单做）。没有用真实模型走过：这次所有回复都来自剧本，界面在真实模型的长回复、慢回复下的表现没有数据。
