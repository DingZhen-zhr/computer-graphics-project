## 修改清单

每条都不放宽检查、不删检查、不针对某个任务写死。等用户批准。

1. **每个任务单独的花费上限**（对应 F1、F6）
   - 改哪里：`benchmarks/run.py` 加 `--task-cap`（默认 ¥2.5，大约是单零件平均花费的 2.5 倍）。一个任务到了就停下，记 `stopped_for_task_cap`，接着跑下一个；总上限照旧。
   - 怎么证明：用假模型写测试，一个任务花到上限后停下，下一个任务照常开始。
   - 影响：多零件任务可能在 ¥2.5 内做不完，会照实记"到任务上限停了"。这是新加的命令行参数，要在 `docs/deviations.md` 记一条。
   - 已改，提交 65c6795。
2. **关节方向反过来时，验收按等价的运动比较**（对应 F3）
   - 改哪里：`benchmarks/assembly_accept.py` 的 `_joint`、`_at_pose`。找到的关节方向和要求的相反时，范围换成 `-hi..-lo` 再比较；`at_pose` 的角度也取反。
   - 怎么证明：单元测试，用同一个铰链的两种写法（+x、0..110 和 −x、−110..0）都通过；真的转错方向的写法照样不通过。
   - 影响：只改判定方式，判的仍是同一个运动，不算放宽。gear_pair 也用 joint 检查，会受同样的规则保护。
   - 已改，提交 c01ff6b（判法按 D43 落实）。
3. **toolbox 隐藏需求补上手算里用到的尺寸**（对应 F4）
   - 改哪里：`benchmarks/tasks/toolbox.yaml` 的 `hidden_spec`，补上提手高 17、握把半径 4、铰链耳外半径 4、各段耳的 x 范围。
   - 怎么证明：加一个测试，检查验收里用到的数都能在隐藏需求里找到（只对这个任务的几个关键数）。
   - 影响：只让模拟用户知道该说什么，验收不变。
   - 已改，提交 4de7780。
4. **智能体不主动加用户没要的修饰**（对应 F2）
   - 改哪里：问答阶段的提示词。倒角、圆角、沉孔这类修饰，用户没提就不加；觉得需要的话在提问里问一句。
   - 怎么证明：更新逐字测试；用剧本测试确认需求单里不再出现"［智能体建议］"的倒角。
   - 影响：所有任务的模型会少一些装饰性倒角。
   - 已改，提交 a62585d、20d3586。
5. **装配碰撞时先查关节方向，再改零件**（对应 F5）
   - 改哪里：多零件建模的提示词，以及装配检查碰撞时的提示文字。刚开始转（离起点不到几度）就碰上，多半是转的方向反了，先把方向或范围反过来试，不要先改零件形状。
   - 怎么证明：更新逐字测试；碰撞提示的单元测试检查这句话会出现。
   - 影响：只影响有转动关节的多零件任务。
   - 已改，提交 3f945a9。
6. **账本按"周末全天空闲价"计价**（对应花费表多记的部分）
   - 改哪里：计价时段判断加一个"只有工作日有高峰"的选项，在 `config.toml` 里打开。
   - 怎么证明：单元测试，周日 15:00 按空闲价算，周一 15:00 按高峰价算。
   - 影响：账本和实际扣费更接近。改之前的记录不重算。
   - 已改，提交 9271418（config.toml 里已经打开）。

  - 没有为了这一轮再改题目或智能体，钱也不够再跑一次。记为 F7（见下）。
- 这一轮没有触发单个任务的花费上限（最贵的 toolbox ¥0.85，上限 ¥2.5）。修改清单第 2、5 条（关节方向等价、碰撞先查方向）这轮的 toolbox 没走到装配，没有得到验证；gear_pair 的关节检查通过了。
