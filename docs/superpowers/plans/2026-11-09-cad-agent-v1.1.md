# CAD 建模智能体第 1.1 版 · 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal：** 能力不降，把每个任务的费用降到基线的 1/3 以下，结果更稳；仍然是"换模型只改配置"。

**Architecture：** 在第一版"程序管流程"的基础上，再做五件事：
- 程序记下完整用量并算钱；
- 每轮开头给模型一张快照，这一轮里只往后追加消息，旧轮折叠，让重复内容走缓存；
- 程序替模型做确定的步骤：自动请确认、改参数自动重建、同一次回复里出错就跳过 build、缺检查不算失败；
- 按阶段选模型，额外参数原样透传；
- 补充"检查写法"和两个留出任务。

**Tech Stack：** 和第一版相同：Python 3.13、simplecadapi 2.2.7、openai SDK、PyYAML、pytest。

**Spec：** `docs/superpowers/specs/2026-11-09-cad-agent-v1.1-design.md`（第一版的设计和计划仍是背景）。

**原文照抄的内容：** `docs/superpowers/plans/2026-11-09-cad-agent-v1.1-prompts.md`。模拟用户提示词和 build 返回格式仍以第一版提示词文档为准。

## Review Focus

1. 模型在需求单未确认时，同一次回复里调用了 `update_brief` 和 `build`：build 被关卡挡住，程序照样自动请确认，不卡死。→ Task 6 `test_build_in_same_reply_blocked_then_auto_confirm`
2. 交付后模型调用的 `update_brief` 什么也没改：不能自动重建，也不能多出一个一模一样的新版本。→ Task 6 `test_no_auto_build_when_nothing_changed`
3. 一轮因为工具调用上限停下，用户说"继续"：新快照里要有上次 build 的完整结果，模型才接得上。→ Task 5 `test_snapshot_after_tool_cap_has_last_build`
4. 接口返回的用量里没有缓存字段，或者干脆没有 usage：各字段记 0，不崩；有价目表时照样算钱（全部按"没命中"算）。→ Task 2 `test_usage_missing_is_zero`、`test_cost_without_cache_fields`
5. 价目表只填了一部分，或填了负数：给出中文报错并指明哪一项，不能静默当 0。→ Task 2 `test_bad_new_sections`

    u = SimpleNamespace(prompt_tokens=100, completion_tokens=50, total_tokens=150, prompt_cache_hit_tokens=80,

判定规则：

  - calls 里没有 ask_user 和 request_confirmation；

主循环的改动：
- 执行一次回复的工具之前，记下 `before = brief_shape(ws.brief)`。
- **C3 跳过 build**：同一次回复里，前面已有调用 `has_error` 为真时，后面的 build 不交给 ToolBox。
  - 它的 tool 消息内容是 `SKIPPED_BUILD_MESSAGE`；
  - 不计失败次数，但计一次工具调用；
  - 日志的 tool 记录里加 `skipped: true`。

    - 然后和模型自己调用 build 走同一条路：交付、计失败、到上限停下都一样；没结束就继续请模型修。

**每条写法的测试方法：**
- 用 `render_notebook` + `run_job` 建一个小模型（同 `tests/test_benchmark_references.py`）。
- 参数正确时，检查通过。
- "做错了的模型"：notebook 里参数的值不变，只在特征代码里把这个参数换成 `(参数 * 1.2)` 一次、`(参数 * 0.8)` 一次，检查都必须不通过。孔数这类计数参数，改成多一个、少一个。
- 写法可以是一到两条检查，例子里写几条，测试就用几条。

参考思路如下（只是起点，以实测为准）：

| 参数种类 | 小模型 | 建议的测法 |
|---|---|---|
| 总体尺寸 | 一块板 | bbox |
| 板厚 | 一块板 | distance：顶面（`normal.z >= 0.99`）到底面（`normal.z <= -0.99`） |
| 孔径 | 板上 1 个通孔 | count：CYLINDER 面，面积在 π·d·t 的 ±5% 内 |
| 孔数 | 板上 n 个通孔 | 同上的选择条件，expected 写孔数参数 |
| 孔位 | 板上 1 个孔 | 孔心处 point_outside，再加一个孔边外 0.5 mm 处的 point_inside |
| 槽或缺口宽度 | 板边开一个缺口 | 缺口两侧墙内外各 0.5 mm 处的 point_outside / point_inside |
| 圆角半径 | 板的一条直棱倒圆角 | count：CYLINDER 面，面积在 (π/2)·r·L 的 ±5% 内 |
| 倒角尺寸 | 板的一条直棱倒角 | count：法向 45° 的 PLANE 面，面积在 √2·c·L 的 ±5% 内 |
| 两面夹角 | 一块倾斜的板 | angle（想清楚两个法向朝哪边） |
