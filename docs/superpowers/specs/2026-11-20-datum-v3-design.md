# 3.0 版设计：新名字、展台界面、会动的多零件、用真实模型把质量做实

日期：2026-11-20　状态：待审阅
前置文档：第二版设计 `2026-11-10-caliper-v2-design.md`。本文没有提到的地方，仍以第二版为准。
设计参考（和用户一起定下来的可交互小样，用浏览器打开就能看；它们用了网络字体和网络上的 three.js，零件是在网页里手捏的，只是参考，不是产品代码）：
- `docs/design/v3-stage-prototype.html`：单零件的展台，含需求单、调参数、坐标轴。
- `docs/design/v3-assembly-prototype.html`：多零件的展台，含零件清单、单独看、炸开、透视、剖开、名字引线、运动条。

## 1. 为什么要做 3.0

第二版的功能做齐了，但用户打开桌面端后的评价是：**色调很丑、全是文字、没有交互感、没有设计感**。前后看了五轮小样才定下新方向（第 4 节）。用户还提出：

1. 换一个名字，"卡尺"不好。
2. **确保建模本身是优秀的**：能满足用户的要求，也能做复杂的东西。
3. **不只做单个零件，要做多个零件，而且能动**（铰链、滑轨、齿轮），参考 teardown 那种能拆开、能动起来的展示方式。
4. **零件本身也要有设计感**，靠提示词和 harness 的规则做到。
5. **作业要求必须全部做到**（第 9 节逐条对照）。

关于第 2 条，有一个必须正视的事实：第二版加的分阶段、终检、看图审查，**从来没有在真实模型上跑过**。现有的测试证明的是"关卡按设计工作"，不证明"真模型做得好"。所以 3.0 必须用真实模型跑评测，并根据真实的失败去改。用户同意为此花钱，但要尽量省（第 8 节）。

## 2. 目标、不做的事、绝对不要的结果

**目标**
1. 改名为 **Datum　基准**，老用户升级时数据不丢。
2. 支持**多零件的产品**：零件之间按连接关系装在一起，可以有会动的关节；程序检查装配和运动过程中有没有撞上。
3. 零件默认有设计感：边角处理、合理的结构、真实的材料。
4. 桌面端整体换成"展台"：零件或产品是画面的主角，其他东西收在菜单和抽屉里。
5. 用真实模型跑两轮评测（单零件 11 个、多零件 3 个），找出失败、对症修改、再复测，如实报告。
6. 作业要求逐条做到，并备好提交材料、演示视频脚本、实验报告初稿。
7. 界面上的文字全部是平常话。

**不做**
图片或手绘作为需求输入（作业里是可选的进阶方向）；英文界面；打包成 .exe / .dmg；把 GitHub 仓库改名；首尾连成一圈的机构（曲柄连杆、四连杆），除非第 5.7 节的探测证明 SCA 能算（见第 5.7 节）。

**绝对不要的结果**
- 界面又回到"满屏方框和文字"。
- 画面上看到的运动，和程序检查碰撞时用的运动不是同一套数。
- 为了让评测好看而放宽检查、删掉检查、或者针对评测任务写死答案。
- 在用户没点头的情况下花钱跑模型，或者花钱超过上限。
- 对外说出没有数据支撑的成功率。

## 3. 约束

- 页面离线可用，不加载任何网络资源。three.js r160 已在项目里。
- 中文用系统字体（Windows "微软雅黑 UI"，Mac "苹方"）；拉丁字母和数字用 **Archivo**（SIL 开源字体许可），字体文件放进项目。这是一个新增的静态资源，本设计文档的批准即视为批准，只限这一个字体。
- 不引入前端框架和构建步骤，延续原生 JavaScript 模块；每个文件不超过 300 行。
- 不新增 Python 依赖。装配、约束、材料、导出都用 SCA 2.2.7 自带的功能。
- SCA 的用法照旧先实测、记进 `docs/sca-api-notes.md` 再用。
- 评测只用 `deepseek-flash`；**3.0 所有真实模型调用合计硬上限 ¥20，按实际扣费算**（口径见第 8.2 节）。
- 所有付费运行，都要执行会话停下来、用户本人点头后才跑。

## 4. 方案对比（已经和用户定过）

### 4.1 界面

| 轮次 | 方案 | 结果 |
|---|---|---|
| 第二版 | 图纸 / 蓝图 | 色调丑、全是文字、没有交互感 |
| 第一轮 | 明亮工作室、暗场工作台、画布优先 | AI 味重（确实是现在 AI 生成界面最常见的套路） |
| 第二轮 | 数显卡尺、切割垫、阳极色块 | 还是丑，不要被"卡尺"限制 |
| 第三轮 | 克莱因蓝、积木、**展台** | 选展台 |
| 第四轮 | 展台的四种气氛 | **浅色用影棚，深色用黑曜** |
| 第五轮 | 多零件版展台 | 认可 |

### 4.2 多零件

| 方案 | 结果 |
|---|---|
| A：装配加拆解查看，零件不动 | 不选 |
| **B：A 再加会动的关节，运动过程中检查碰撞** | **采用** |

参考了 teardown（elvarofficial/teardown，MIT 许可，一个把机器做成能拆、能动的 3D 网页的 Claude 技能），借鉴四点：一个零件一个按钮、可以单独看；剖切、透视、带引线的名字；**一个输入驱动全部运动，画面和数据来自同一个来源**；碰撞要靠改尺寸解决，不能靠换镜头藏起来。

### 4.3 建模质量

| 方案 | 结果 |
|---|---|
| 不花钱，不跑真实模型 | 没法确保质量，不选 |
| 只跑一轮 | 能找到问题，但没法验证修改有没有用，不选 |
| **两轮：全部跑一遍找问题，修改后只重跑失败的和几个对照，空闲时段跑** | **采用** |

### 4.4 名字

候选 Datum 基准、Billet 坯、Plinth 展台、Facet 刻面。采用 **Datum**：CAD 里所有尺寸都从基准量起，对应"每一步都拿实测说话"。

## 5. 多零件与运动（内核）

### 5.1 用户这边的流程

1. **问清楚**：除了尺寸，还要问清由哪几个零件组成、零件之间怎么连、哪里会动、动多少。
2. **确认**：需求单变成"零件清单 + 怎么连 + 怎么动"，用户确认后才开始做。
3. **一个零件一个零件地做**：每个零件都走第二版的分阶段流程（先写检查、再建模、实测通过才往下、每个零件各自做终检）。
4. **装起来**：按连接关系装到一起，检查对齐、穿模、间隙。
5. **动起来检查**：每个会动的地方从头到尾取若干位置，每个位置都检查零件之间有没有撞上。
6. **交付**：整个产品存成一个版本（第 5.6 节）。

只有一个零件的需求，走第二版原来的流程，不受影响。

### 5.2 需求单

需求单加三样东西，都由程序校验格式：

- **零件清单**：每个零件有编号、名字、材料，以及它自己的组成部分。
- **产品参数和零件参数**：产品参数（比如工具盒的长宽高）可以被多个零件共用；零件参数只属于一个零件。单位、来源（你给的 / 建议）规则不变。
- **连接与运动**：每条写清哪两个零件、怎么连（固定、同轴、贴平）、会不会动、怎么动（转动或滑动）、动的范围、是否和别的运动联动（齿轮、齿条、皮带按传动比联动）。

确认规则沿用第二版：零件清单、连接与运动都要写全才能请用户确认；确认后再改这些，确认状态清零。

### 5.3 模型怎么描述装配

和第二版"模型不写样板代码"的原则一致：**装配由模型用工具写成声明，程序把它翻译成 SCA 的装配代码。**

- **零件上的连接点**：模型在零件里声明命名的连接点，例如"盒体的铰链轴线"。连接点**必须挂在零件的真实几何上**：用和检查一样的选择条件选中一个圆柱面（取它的轴线）、一个平面（取它的位置和法向）或一条边，可以再加一个用参数写的偏移。程序会检查选中的几何确实存在且只有一个，悬空的坐标框不被接受。
- **配合**：两个零件的连接点之间是什么关系（同轴、贴平、固定、偏移多少）。SCA 本身只有"固定"和几种运动约束，没有"同轴""贴平"，所以由我们的代码把配合翻译成"带偏移的连接点 + SCA 的固定或运动约束"，算出每个零件的摆放位置。
- **关节**：在某个配合上声明会动，类型（转动、滑动）、范围、在界面上叫什么名字（例如"盖子翻开"）。一个产品可以有几个独立的关节，每个对应界面上的一条运动滑条。
- **联动**：齿轮、齿条、皮带按传动比，由一个关节带动另一个。
- 具体的工具名、参数格式，在实施计划的"原文照抄"里给出，并照旧逐字测试。

### 5.4 运动的唯一来源

- 每个关节在它的范围内均匀取若干位置（默认 24 个，可配置）。**每个位置上各零件的摆放，由内核算好**（用 SCA 转动和滑动约束自带的驱动值，见第 5.7 节），存成一个运动数据文件。
- 碰撞检查用的就是这些位置；界面播放运动时也只读这个文件，在相邻两个位置之间插值。
- 检查一个关节时，其他关节停在各自的初始位置。
- 联动的关节在同一份数据里一起算。

### 5.5 装配和运动的检查

在第二版检查类型的基础上增加：

| 检查 | 意思 |
|---|---|
| 不穿模 | 两个零件之间重叠的体积接近 0 |
| 间隙 | 两个零件之间的最短距离不小于某个值 |
| 同轴 / 贴平 | 两个连接点的轴线或平面对齐，偏差在容差内 |
| 运动中不碰撞 | 关节在所有取样位置上，指定的零件之间都不穿模 |
| 能动到位 | 关节能走完声明的范围，中间不出错 |
| 传动比 | 联动关节之间的转动比例符合声明 |

程序自动加、模型删不掉的必做检查：
- 每个零件实体有效且只有一块；
- 每个连接点都落在真实几何上（第 5.3 节）；
- 装好后**任意两个零件之间都不穿模**；
- **每个关节运动中都不碰撞**。

"接触"配对（允许极小的重叠）**只能由程序从配合里推出来，模型不能自己声明**：齿轮联动的两个齿轮、同轴配合里轴和孔的那一对。它们用很小的固定容差（由第 5.7 节第 5 条的实测定），不是放开不查。

"同轴""贴平"检查**量的是真实几何**：同轴量两个零件上被选中的圆柱面的轴线，贴平量两个被选中的平面，而不是量连接点自己（连接点是按配合摆过去的，量它必然通过，等于没查）。

参数扰动验证照旧对产品参数和零件参数都做。

### 5.6 存储和交付物

- 会话目录按零件分开：用第二版留好的 `Session.part_dir(part_id)`，每个零件一个子目录，装配和运动数据放在会话根目录。
- 每个版本里有：**每个零件的参数化源文件（SCA notebook）、STEP、STL**；**装配 notebook**（按 SCA 的约定，用 `scad.use` 引用各零件 notebook）；**整个产品的 STEP**；运动数据文件；检查结果；需求单。
- 和 SCA 的 `scad.use` 相关的三件事（来自复核时读到的 SCA 文档，实施时以实测为准）：
  - 现在拼出来的单零件 notebook 把编号写死成 `model`。多零件时每个零件 notebook 用**零件自己的编号**，否则组装时会报编号冲突。单零件需求照旧用 `model`，单零件 notebook 的文本一个字不变，旧测试不受影响。
  - `scad.use` 传入覆盖值时，被覆盖的变量所在的整个 cell 不再运行，所以零件 notebook 的参数必须单独放一个 cell（现在已经是这样），组装时要把这个 cell 里的全部参数一起传进去。
  - 现在的沙盒运行程序读的是单个零件的实体；装配要单独的运行方式。
- 材料：SCA 的材料只有颜色。我们自己的需求单里另记材料名（铝阳极氧化、ABS 等），界面按材料名选渲染的质感；颜色写进 SCA 的材料，导出的文件里也带着。

### 5.7 先探测、再动手

实施计划的第一个任务是探测并记进笔记：

1. SCA 的装配、连接点、约束、求解在本机能不能跑通，整个产品能不能导出 STEP。
2. 能不能把一个零件摆到指定位置后，算两个零件的重叠体积；一次碰撞检查要多久（决定默认取几个位置）。
3. SCA 的转动约束有驱动角度和角度范围，滑动约束有驱动距离和距离范围（文档里写着）。实测它们能不能把关节驱动到指定位置。不能的话，关节的位置由我们自己的代码按转轴算，SCA 只负责把零件摆过去和检查重叠。
4. **首尾连成一圈的机构**（曲柄连杆）：SCA 文档说解不开时会退回到在范围内搜索。"能解"的标准定为：在全部取样位置上约束误差都小于容差，而且同一个输入两次求解结果一致。达到就支持；达不到，这一版不做，在 README 和报告里写明。
   - SCA 文档有一处说装配约束的接口"暂时移除"，而接口文档里这些函数都在。以实测为准。
5. 标准件齿轮做成的一对齿轮，按正确中心距装好后，重叠体积有多大，用来定"接触"配对的容差。

### 5.8 多个零件在一轮对话里怎么做完

- 用户确认之后，一轮对话里一口气做完全部零件、装配和运动检查，用户不用每个零件说一次"继续"。
- 上下文按零件折叠：一个零件做完（它自己的全部步骤和终检都过了），这个零件的全部来往换成一段小结（零件名、参数、连接点、检查数），下一个零件从干净的上下文开始。做法和第二版"阶段通过就折叠"一样。
- 上限按零件放大：每轮的工具调用总上限 = 每个零件 200 次 × 零件数 + 装配 100 次；每一步失败 3 次的上限照旧按步计（第二版里阶段通过就清零）。
- 界面的"正在做"按零件推进：零件清单里当前零件在闪，做完的打勾。

## 6. 零件的设计感

靠提示词规则和程序的默认做法：

1. **收尾步骤**：每个零件的计划默认最后一步是"边角处理"：外露的边倒圆角或倒角，孔口倒小角。半径按零件尺寸给建议值、来源标"建议"。用户给的尺寸一个不动；用户说不要圆角就不做。
2. **结构讲究**写进提示词：壁厚统一；零件之间留合理的间隙；会动的地方留足避让；受力的地方加筋或加厚。
3. **材料**：每个零件都有材料（铝阳极氧化、ABS 塑料、不锈钢、橡胶等）。颜色写进 SCA 的材料，材料名记在需求单里，界面按材料名渲染质感（第 5.6 节）。
4. **一个强调色**：界面里会动的零件用强调色，其他零件用材料本色。
5. **没给的比例按常见产品来**：用户只说"做个工具盒"时，建议值参考常见产品的比例，标成"建议"。
6. 看图审查（第二版已有）在能看图的模型上，额外问一句"看起来是不是一件做工好的产品"。DeepSeek 看不了图，这一项自动跳过。

## 7. 界面

### 7.1 总体结构

单零件的布局：

```
┌───────────────────────────────────────────────────────────┐
│ [≡ 菜单]                  零件名                  [坐标轴]  │
│                     第 2 版  100 × 60 × 5 毫米     前上右立体底│
│  ● 第 1 步 ✓                                        9/9    │
│  ● 第 2 步 ✓          （零件在舞台中间）          全部量过   │
│              模型说的话，像字幕一样在这里                    │
│                  [选项一]  [选项二]                         │
│ [对话记录]       [ 接着说要改哪里…        ↑ ]      [调参数] │
└───────────────────────────────────────────────────────────┘
```

多零件的布局（见 `v3-assembly-prototype.html`）：

```
 [≡]                      工具盒                        [坐标轴]
                      第 1 版，4 个零件
  零件，点一个单独看
  ● 盒体   6/6                                         18/18
  ● 盖子   6/6          （装好的产品）                  全部量过
  ● 铰链轴 3/3                                       [零件小卡片]
                 ┌ ▶ 盖子翻开 ────●──────── 70° ┐
                 │ 翻到哪个角度都没有碰到别的零件  │
                 └───────────────────────────────┘
 [炸开━━] [透视] [剖开] [名字]  [接着说要改哪里… ↑]     [调参数]
```

- 整个窗口就是一个舞台。可以拖着转、滚轮缩放、右键平移。
- **舞台中间永远放"现在正在做的东西"**（第 7.3 节）。
- 其他功能收在菜单、对话记录、检查面板（点大数字）、调参数里，点了才出来。

### 7.2 外观

- 跟随系统，也可以在设置里手动选。
- 浮在舞台上的东西用半透明加背景模糊的"玻璃"质感，圆角是胶囊形或 20px 左右；不用方框套方框。
- 动效只在有意义的地方：抽屉滑出（约 300ms）、需求单飞走、零件按步骤长出来、视角平滑切换、运动播放。遵守系统的"减少动态效果"设置（运动不自动播放）。
- 零件按材料渲染；每个零件有淡淡的轮廓线。
- 具体数值以两个小样为准，实施时可以微调，不改方向。

### 7.3 舞台中间放什么：跟着进度走

| 进度 | 舞台中间 | 顶上的标题 | 字幕和选项 |
|---|---|---|---|
| 刚开始 | 一句引导和三个可以点的例子（至少一个是多零件的） | 新零件 | 无 |
| 正在问问题 | **需求单**，边聊边填；还没问到的写"等你回答" | 新零件 / 还在问你几个问题 | 模型的问题；能给选项的给按钮 |
| 都问完了 | 需求单，下面"没问题，开始做"和"我还要改" | 名字 / 都记下了，你看一下 | |
| 正在做 | 需求单飞走；零件按步骤长出来；多零件时左边零件清单显示每个零件的进度，装配时零件依次就位 | 名字 / 正在做，第几步 | 正在做什么 |
| 做好了 | 完整的零件或产品；右边"N/N 全部量过，都对"；有关节时出现运动条 | 名字 / 第几版 | 模型的话和选项 |
| 没做成 / 停下了 | 停在最后一步 | 名字 / 没做完 | 原因和下一步可以怎么做 |

- 做好以后想再看需求单：点顶上的名字。
- 模型一次问多个问题时，字幕变成一张小卡片，每个问题一行、各带输入框。

### 7.5 多零件的看法

- **零件清单**（左侧）：每个零件一行，色块是它的材料色，后面是它的检查数。点一个就单独看：其他零件变得很淡，右边出现小卡片（尺寸、材料、检查数）。"看全部"恢复。
- **运动条**（底部）：每个关节一条，左边播放 / 暂停，中间滑条，右边当前值；下面一排小点表示检查过的位置，没撞是绿色，撞了是红色并且零件上标出撞到的地方。几个关节时可以切换。
- **炸开**：滑条，零件沿装配方向分开（方向由配合关系推出来）。
- **透视、剖开、名字**：三个开关。名字带引线，标签不挡住零件，单独看某个零件时只显示它的名字。

### 7.6 调参数

- **出现时机**：做好第一个版本之后。
- **位置**：从底部升起的面板，舞台往上挪，零件不被挡住。
- **内容**：单零件按组成部分分组；多零件按"产品"和各零件分组。分组规则：参数说明里提到哪个组成部分或零件的名字就归到那一组，归不进去的放"其他"。每行：名字、滑条、数字框、单位。改过的行有标记线。
- **参数的中文名**：从参数说明开头截取，截到第一个逗号、括号或冒号为止；截出来是空的就用参数名。
- **预览**：松开滑条或改完数字后，程序在后台只生成模型、不跑检查（几秒钟），显示"正在预览"，好了换成预览的样子，轮廓用虚线区分。不存版本。
- **应用**：走第二版的 `apply_params`（多零件时扩展成对产品重新做一遍：各零件、装配、运动检查）。全过存成新版本；没过退回原值，说明哪条没过，给一个"让模型帮我处理"。它不做"每个尺寸都起作用"那一步，界面文字不能说做了。
- 底部说明："改好后点'应用'，会从头重做一遍、再量一遍。不花钱。"

### 7.7 看的方式

- 不限制上下角度，能转到底下看；转到地面以下时地面影子和网格自动隐藏。
- 右上角坐标轴小图：X 红、Y 绿、Z 蓝，**Z 朝上**，点一个轴就平滑转过去；下面五个按钮：前、上、右、立体、底。
- **剖开**：开关加滑条。
- **尺寸标注**：开关。画出外形尺寸；在调参数面板里鼠标停在某个参数上时，用到它的检查所选中的几何，在零件上各标一个点（几何中心）。
  - 内核要加一处改动：检查结果多一个字段 `selected`，最多 8 项，每项是几何类型、中心点，面再加法向。只有按条件选几何的检查才有。旧会话没有就不画。
- **正交视图**：开关。

### 7.8 修改前后的对比（作业要求）

作业要求"展示修改前后的模型"。版本页签里任选两个版本，点"对比"：
- 舞台上同时显示两个版本：新版本是实体，旧版本是半透明的轮廓叠在同一位置；变了的地方一眼可见。
- 也可以切成"并排"：左右两个视图，转一个另一个跟着转。
- 下方列出参数变化（`hole_d：6 → 8 毫米`）和检查结果的变化。

### 7.9 文字的规矩

界面上一律说人话，不出现程序内部的词。对照表（实施计划里列全）：

| 不要写 | 写成 |

| 阶段 S2 | 第 2 步 |
| 需求单确认 | 没问题，开始做 |
| 参数扰动验证 | 每个尺寸都确认过真的起作用 |

### 7.10 新接口

- `POST /api/sessions/<id>/preview`：用新参数生成 STL，不跑检查、不存版本；同一会话只跑一个，新的取消旧的；对话进行中拒绝。
- 状态里增加：零件清单和每个零件的进度、检查数、材料色；关节列表；运动数据文件的地址；每个参数的分组和中文名；检查的 `selected`；两个版本的对比数据。
- 文件白名单增加：各零件的 STL、STEP、notebook，装配 notebook，运动数据文件。

## 8. 建模质量

### 8.1 评测任务

- 单零件 11 个：简单 5 个（手机支架、法兰盘、L 形支架、电路板小盒、阶梯轴），中等 3 个（轴承座、电池盒、直齿轮），困难 3 个（散热器、三通管接头、支架臂）。
- **新增多零件 3 个**：带铰链盖的工具盒（转动）、带抽屉的小柜子（滑动）、装在支架上的一对啮合齿轮（齿轮联动）。每个照旧写一句话的需求、隐藏的完整需求、一次修改请求、人工验收（含装配和运动的验收）；每个都要有一份标准答案，用真实 SCA 装得起来、动得起来、通过验收。
- **留出任务**（只测，不读对话记录，不为它们改任何东西）：阶梯轴、电池盒、支架臂、装在支架上的一对啮合齿轮。其余 10 个是开发任务，转动（工具盒）和滑动（抽屉柜）都在开发任务里。
- 多零件的自带案例放三个，覆盖转动、滑动、齿轮联动，都和评测任务不是同一个东西（例如：带门的小柜子、滑台、齿轮带动的转盘），齿轮联动的案例不能和留出任务的结构一样。
- **多零件的验收怎么对上模型起的名字**：验收不依赖零件名和关节名。
  - 装好后的验收按世界坐标写（外形尺寸、点在不在材料里），坐标约定照旧：底面贴 z=0、xy 居中、最长的方向沿 x。
  - 运动的验收写成"绕某个方向、经过某一点附近的转轴，能转到某个角度"或"沿某个方向能滑出多少"。评测脚本按转轴的方向和位置去产品里找对应的关节，找不到就算这一项没过。
  - 找到之后，**评测脚本自己用 SCA 把关节驱动到验收要求的位置再量**，不读内核写的运动数据文件，免得自己验自己。
  - 阶梯轴从 1.1 版起就是留出任务，一直干净。电路板小盒在 1.1 版失败后第二版专门针对它加了关卡，已经不干净，改为开发任务，报告里写明。

### 8.2 两轮评测

1. **准备**（不花钱）：
   - 评测脚本能一次跑完 14 个任务，按开发 / 留出、单零件 / 多零件分开出表；表里有作业要求的四项：是否成功、尺寸偏差、耗时、修复次数。
   - **真正的硬上限**：每次调用模型后都累计花费，到上限立刻停，已跑完的照常写出。
   - **账本和口径**：3.0 里所有真实模型调用都记进同一个账本：两轮评测、可选的对照、录演示视频；智能体和模拟用户的调用都算。`--budget 20` 管的就是这个总额，**按实际扣费算**。
   - 为了按实际扣费算，价目表分两套：高峰价和空闲价，再加空闲时段的起止时间，都由用户照 DeepSeek 官网填。脚本按当前时间用对应的价格累计。
   - **默认只在空闲时段跑**：不在空闲时段时脚本不开跑；跑到一半出了空闲时段，从那一刻起按高峰价累计（不中断正在跑的任务，但下一个任务不再开始）。用户明确加 `--allow-peak` 才能在高峰时段开跑。
   - 第 8.4 节的提示词改动在这一步做完。
2. **第一轮**（空闲时段，预计 ¥7–13）：14 个任务各跑 1 遍，开关全开。**跑之前停下来问用户。**
   - 这个数是粗估：单零件按 1.1 版实测的单价推，多零件按每个约等于 3–4 个单零件推；第二版的分阶段流程调用会更多，实际可能偏高。如果第一轮就花了 ¥13 以上，第二轮只重跑最要紧的失败任务，保证总额不超 ¥20。
3. **失败分析**（不花钱）：只读开发任务的对话记录，把每个失败归类（没问清需求、计划拆得不对、建模写法不会、检查写错、关卡误伤、装配写错、运动碰撞、流程卡住、上限太小等），写进 `docs/results-v3.md`，并列一份**修改清单**：每条对应哪个失败、怎么改、怎么测。**写完停下**，规划会话核对、用户批准后才改。
4. **对症修改**（不花钱）：只做批准过的条目。可以改提示词、速查表、工具说明、自带案例、上限数值、关卡细节。不可以放宽检查、删除检查、针对评测任务写死内容。每处改动都要有不花钱的测试。
5. **第二轮**（预计 ¥4–7）：重跑第一轮失败的任务，加 2–3 个原来就通过的开发任务，加全部留出任务。**跑之前停下来问用户。**
6. **可选：经验复用的对照**。如果账本里还有余额，问用户要不要把开发任务里的几个在"关掉案例库"的条件下再跑一遍，给报告里"经验复用"提供对照数据。不在上限内就不做。
7. **报告**：`docs/results-v3.md` 写各轮的数字、花费、每个失败的原因和处理、留出任务的结果；README 的"验证到什么程度"换成真实数字。

### 8.3 目标（是目标，不是门槛，达不到如实写）

- 单零件开发任务：简单的全部做成；中等至少 2 个；困难至少 1 个。
- 多零件开发任务：至少 1 个做成（装得起来、动得起来、全程不碰撞、通过验收）。
- 留出任务如实报告。
- 合计花费不超过 ¥20。

如果第一轮显示 flash 在困难任务或多零件上基本做不出来，停下来和用户商量是否给规划和建模换更强的模型，不自己换。

### 8.4 模型说话的方式

系统提示词加一节"和用户说话"：不说内部的词（阶段编号、检查 id、工具名、英文术语），用"第几步""量过了""这个尺寸""碰到了"这类说法。照旧逐字测试。
