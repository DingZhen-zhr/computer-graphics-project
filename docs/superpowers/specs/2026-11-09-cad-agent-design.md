# CAD 建模智能体 · 第一版设计

日期：2026-11-09　状态：待审阅
来源：AICG Project 3 作业要求（github.com/syby119/AICG-projects/tree/main/projects/project3）

## 1. 目标与范围

**第一版要做到：** 作业"基础任务"五条全部能跑通、能演示；同时搭好一个"换模型也能用"的框架。

**第一版不做：** 经验复用（定为进阶方向，放第二版）、图片输入、装配、自己写 3D 查看器。

**已知条件：** 4 人小组；时间充裕；大模型未定（大概率 DeepSeek），先用 DeepSeek 试；本机 Windows 11 + Python 3.13；SCA 版本 2.2.7（有 Windows + Python 3.13 安装包）。

**成功标准：**
- 第 9 节的 3 个测试任务，都能从模糊需求一路走到交付。过程中要出现追问、至少一次检查不过后自动修好、至少一轮修改。
- 换模型只改配置文件，不改代码。
- 每个会话留下：对话和工具调用日志；每个版本的 `.py`、`.step`、截图、检查报告。

## 2. 核心思路：程序管流程，模型只做判断

"让任何模型都能做好"落实为四条规则：

1. **模型不写样板代码。** marimo 文件结构、每个 cell 的输入输出、导入语句、最后的 `Part`，都由程序拼。模型只写每个特征的几行建模代码。
2. **关卡由程序判定，不靠模型自己说。** 需求没确认就不能建模；检查没有全过就不能交付；重试到上限就停下来报告。
3. **报错要翻译。** 返回给模型的是"哪个特征、什么问题、相关数值"，不是几百行原始堆栈。
4. **工具小而明确。** 每个工具的输入输出都是简短 JSON，能力弱一点的模型也能用对。

## 3. 方案选择：模型怎样驱动 SCA

| 方案 | 做法 | 问题 |
|---|---|---|
| A 整份写 | 每次让模型输出整个 `.py` | 每次重写容易把对的地方改坏；报错难定位；改一个尺寸也要全部重写 |
| B 一个操作一个工具 | 把 make_box、cut、fillet 等逐个包成工具 | 要把 SCA 几十个函数重包一遍；调用链很长，模型容易半路走偏；参数化源文件还得反推 |
| **C 按特征编辑（采用）** | 程序维护一份"特征列表"，模型用工具增、改、删单个特征，程序拼成标准 SCA notebook 再运行 | — |

选 C 的理由：
- 报错自然落在某一个特征上，修复范围小。
- 改尺寸只动参数，不动特征代码。
- 拼出来的 `.py` 就是作业要的参数化源文件，符合 SCA 的特征树写法，能直接用 `sca edit` 打开。

## 4. 整体流程

```
澄清 ──用户确认需求单──▶ 建模 ⇄ 检查（不通过就自动重试，最多 3 次）──全部通过──▶ 交付
 ▲                                                                          │
 └───────────────────────────── 用户提出修改 ◀──────────────────────────────┘
```

- **澄清：** 模型整理需求单；有缺项就用 `ask_user` 追问；需求单完整后，程序把它展示给用户，用户确认后才放行。
- **建模：** 模型写参数、写特征、写检查项，然后调用 `build`。
- **检查：** 程序运行模型、跑完所有检查，把结果交回模型。不通过记一次重试。
- **交付：** 全部检查通过时，程序自动保存版本 vN（`.py`、`.step`、截图、检查报告），展示给用户。交付不由模型调用。
- **修改：** 用户发新消息 → 回到澄清，只更新涉及的条目 → 建模。旧的检查项保留，所以没改的需求会被自动复查。
- **重试用完：** 停下，把最后一次失败原因告诉用户，问下一步怎么办。
- **防止死循环：** 每轮用户消息内，模型调用工具的总次数上限为 40 次（可配置）。

## 5. 需求单

JSON 格式，由程序保存，每轮都带给模型。

```json
{
  "part": {"name": "手机支架", "purpose": "放桌上看视频"},
  "params": [
    {"name": "phone_w", "value": 78, "unit": "mm", "source": "user", "note": "带壳手机宽度"},
    {"name": "tilt_deg", "value": 65, "unit": "deg", "source": "suggested", "note": "支撑角度"}
  ],
  "features": ["底座", "倾斜支撑面", "底部托唇", "托唇中间的充电缺口"],
  "open_questions": [],
  "confirmed": false
}
```

规则：
- `source` 区分"用户给的"和"智能体建议的"，这是作业示例明确要求的。
- 只有 `open_questions` 为空**且** `confirmed` 为真时，才允许进入建模。
- 确认之后再调用 `update_brief` 时：
  - 只改动 `source=user` 的条目（来自用户原话），确认状态保留；
  - 新增或改动了 `source=suggested` 的条目，或新增了待问问题，确认状态自动清零，需要重新确认。
- 每次修改时，程序比较新旧需求单，把"改了什么"写进日志和版本说明。

## 6. 给模型的工具

**澄清阶段**
- `update_brief(patch)`：修改需求单
- `ask_user(questions)`：向用户提问；本轮结束，等用户回答
- `request_confirmation()`：把需求单展示给用户确认；本轮结束，等用户回答

**建模阶段**
- `set_params(params)`：写参数（名称、数值、单位）
- `upsert_feature(slug, role, code)`：新增或替换一个特征；`role` 取 build / add / subtract / intersect / modify / pattern
- `remove_feature(slug)`
- `set_checks(checks)`：写检查项（格式见第 8 节）
- `build()`：运行模型并检查，返回结果
- `inspect(query)`：查询当前模型的事实，如包围盒、体积、某类面或边的数量和位置，供模型排查问题
- `api_help(name)`：查询 SCA 某个函数的用法（从随项目附带的 SCA 文档摘要里取）

程序拼文件时：
- 自动分析每段特征代码用到了哪些名字，生成 cell 的输入和返回值；
- 参数放最前面一个 cell，`Part` 放最后一个 cell；
- 特征顺序按模型给出的顺序，`upsert_feature` 替换时位置不变。

## 7. 运行与安全

- **静态检查：** 只允许 `import simplecadapi` / `from simplecadapi import ...` / `import math`；禁止 `open`、`exec`、`eval`、`compile`、`__import__`、`os`、`sys`、`subprocess` 等。不通过就直接把原因返回给模型，同样计一次重试。
- **独立子进程运行：** `python -I`；工作目录限定为会话目录；环境变量中去掉 API key；超时 60 秒（可配置），超时就结束进程，计一次失败。
- **结果格式：** 子进程把结果写成 JSON，包括每个 cell 的状态、出错的 cell 和精简后的错误、参数值、所有检查结果。

## 8. 检查器

检查项由模型根据需求单来写，但只能用下面几种固定类型。测量由程序完成，模型不写测量代码。

| 类型 | 用途 | 例子 |
|---|---|---|
| 必做（程序自动加，模型删不掉） | 实体有效、只有一个实体、体积大于 0 | — |
| `bbox` | 整体或某个方向的尺寸 | 底座长度 = `base_l` |
| `count` | 满足条件的面或边的数量 | 半径 = `bolt_d/2` 的圆柱面有 `bolt_n` 个 |
| `angle` | 按条件选出的两个平面之间的夹角 | 支撑面与底面夹角 = `tilt_deg` |
| `point_inside` / `point_outside` | 某个点在或不在材料里 | 缺口中心是空的；孔是通的 |
| `distance` | 两组几何之间的最小距离 | 孔中心到边缘 ≥ 8 |

- **期望值：** 可以写数字、参数名或表达式（如 `"phone_t + 2*clearance"`），参数改了检查会跟着变。
- **容差：** 长度默认 ±0.1 mm，角度默认 ±0.5°，每条可以单独设置。
- **覆盖规则：** 每个 `source=user` 的参数至少要被一条检查引用。不满足就拒绝交付，并告诉模型缺哪几个。
- **结果里附带选中的几何：** 每条检查都会附上"选中了几个、各在什么位置"，方便模型和人核对选得对不对。

## 9. 测试任务（第一版先定 3 个，后续可换）

1. **手机支架**（作业示例）：倾斜支撑面 + 底座 + 托唇 + 充电缺口。考查：追问、角度检查、缺口检查。
2. **法兰盘：** 旋转体 + 阵列螺栓孔 + 圆角。考查：阵列、孔数、分布圆直径、圆角。
3. **带加强筋的 L 形安装支架：** 拉伸 + 多次布尔 + 安装孔 + 倒角。考查：多次布尔运算、孔位置。

每个任务写成一个 YAML 文件，内容包括：
- 初始的一句话需求；
- "用户心里的完整需求"（隐藏答案）；
- 修改请求；
- 人工写的验收检查和容差（与智能体自己写的检查分开，用同一套检查器计算）。

**自动测试时的用户：** 由一个模拟用户扮演。它也是一个大模型，手里拿着隐藏答案，只回答被问到的内容，被问到隐藏答案里没有的就答"你定吧"。

**测试脚本输出：** 是否成功、各尺寸偏差、耗时、修复次数、模型调用次数、token 用量，汇总成一张表。

## 10. 命令行界面

- 普通输入就是和智能体对话。
- 每次交付后打印检查结果表和截图路径。
- 命令：
  - `/view`：用 `sca edit` 在浏览器里打开当前模型
  - `/diff`：对比修改前后（参数变化 + 两张截图）
  - `/versions`：列出所有版本
  - `/quit`：退出

## 13. 风险与应对

- **路径含中文：** OpenCASCADE 在 Windows 上读写含中文的路径可能失败。第一步先验证；如果失败，就把会话目录配置到纯英文路径。
- **verify 附加包（OCP）装不上：** 第一步验证。装不上就只用 SDK 自带的测量函数，检查器里依赖 OCP 的类型（`point_inside`、`distance`）改用 SDK 能做到的方式，或暂缓。
- **模型不熟悉 SCA：** 靠三样东西补：提示词里的常用函数速查表、`api_help` 工具、翻译后的报错。
- **检查条件写错导致误判：** 检查结果附带被选中几何的数量和位置，让模型自己能发现选错了。
