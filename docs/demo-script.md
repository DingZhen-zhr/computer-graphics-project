# 演示脚本

录一段 4–6 分钟的视频，按作业要求的四个镜头走。每个镜头写了要说的话、要点哪里、预计看到什么、大概多少秒。
窗口开到 1600×1000 左右，浅色。录之前先看最后的检查清单。

## 镜头 1：需求输入（约 70 秒）

- **说：** "我只说一句很模糊的话，看它怎么把需求问清楚。"
- **点：** 菜单 → 做一个新的；在底部输入框输入"做一个带铰链盖的工具盒"，回车。
- **看到：** 舞台中间出现需求单卡片，标题"工具盒"，下面列出零件（盒体、盖子、铰链轴、提手）和已经知道的尺寸；问到的值显示"等你回答"。字幕里是它问的两个问题（铰链轴离后壁多远、盖子最多翻多少度），带建议值。
- **说：** "它先把能定的定下来，标了'你给的'和'建议'；拿不准的才问我。"
- **点：** 回答"铰链轴离后壁 5 毫米，盖子最多翻开 110 度"。
- **看到：** 需求单填齐，下面出现"没问题，开始做""我还要改"两个按钮。

## 镜头 2：自动建模（约 90 秒）

- **点：** 没问题，开始做。
- **看到：** 需求单向上飞走；左边的零件清单里当前零件在闪；每做完一个打勾；四个零件都做完后，副标题变成"正在装起来"。
- **说：** "每个零件都是一步一步做的，每一步做完程序都实测一遍尺寸；四个零件做完再装起来，检查有没有穿模、盖子翻开时会不会碰到盒子。"
- **看到：** 做好了：右边大数字"36/36 项全部量过，都对"，底部出现运动条。
- **点：** 运动条的播放；拖一下滑条；点零件清单里的"盖子"单独看；左下"炸开"拉到一半、"透视"打开。
- **说：** "运动条播放的就是程序检查碰撞用的那一组位置，下面每个小点是一个检查过的位置。"

## 镜头 3：反馈修正（约 60 秒）

- **点：** 左下"对话记录"，展开某一步的"做了 N 件事"。
- **看到：** 某一步里"build"没过、模型改了特征、再 build 通过的过程（每一行写着做了什么、哪里出错）。
- **说：** "这里它做出来的尺寸和需求不一样，程序量出来以后把差多少、哪个面告诉它，它自己改好了。"
- 如果这次录制刚好一次修复都没有：打开计划 4 第二轮评测里一次真实的修复记录（结果目录和任务写在 `docs/results-v3.md` 的"第二轮"一节），说明这是评测时的真实记录。

## 镜头 4：多轮修改（约 70 秒）

- **点：** 输入"盖子最多翻到 95 度就够了"，回车。
- **看到：** 交付第 2 版，运动条的范围变成 0–95°。
- **点：** 右下"调参数"，把"盒子高度"从 60 改成 70，点"应用"。
- **看到：** 提示"已存为第 3 版"；舞台上盒子变高。
- **点：** 左下"版本"，在第 3 版上点"对比"；切换"叠在一起"和"左右并排"。
- **看到：** 下面列出"box_h：60 → 70 毫米"这类变化。
- **说：** "改数值不用再问模型，程序直接从头重做、再量一遍；不花钱。"

## 单零件版（时间不够时用）

用"做一个放在桌上看视频的手机支架"走一遍镜头 1、2、4：提问 → 需求单 → 左边的步骤一步步打勾 → 做好了 → 调参数改倾角 → 对比。

## 录制前的检查清单

- key 已经在 Datum 的设置里存好（"测试连接"通过）。
- 价目表（高峰、空闲两段）已经填在设置或配置里。
- 尽量在空闲时段录（便宜）；录之前看一眼账本余额（`benchmarks/results/ledger-v3.json`）。
- 网络正常；关掉别的占网速的程序。
- 窗口大小 1600×1000 左右；浅色；系统缩放 100% 或 125%。
- 先关掉通知、免打扰打开。
